## Major findings

### M1 · The public README still describes a 3-module project — RESOLVED 2026-09-13

`README.md` is the repository's front page and is now badly wrong. It understates the project
by eleven modules.

- line 7 — badge reads `status-early — part 1 of 5`
- lines 48–58 — every module 4–14 is marked `⏳` (not written)
- Project status section — still "3 modules, 10 lessons, 23 questions, 3 binary labs"
- the labs table still says .NET/JAR/APK/PYC "lands in Module N"

Reality: 14 modules, 54 lessons, 125 questions, 20 labs.

**Fix:** update badge, table, counts and labs table. Low effort, high visibility.

### M2 · The quiz linter created an inverse bias — correct answers are now too short

**This is a defect in the rule I wrote, not in the other session's questions.** The gate only
forbids the correct option being the *longest*. Authors satisfying it drifted to the other end.

Measured across all 125 questions:

```
correct is STRICTLY shortest : 47 / 125 = 38%   (chance = 25%)
correct is strictly longest  :  0               (linter forbids)
no option shorter than correct: 65 / 125 = 52%
```

38% against an expected 25% is z ≈ 3.3 (p ≈ 0.001) — not noise. And it is spread across every
module, mine included (modules 1–3 contribute 13 of the 47), so it is systemic to the rule.

The original complaint was "I could pick the longest answer without reading the question."
A learner can now do a weaker version of the same trick in reverse.

**Fix:** make the rule two-sided in `scripts/lint-quizzes.ts` — fail when the correct option is
strictly shortest as well as when it is strictly longest. That will reject roughly 47 existing
questions, each needing a distractor trimmed or the correct option lengthened. Per the project's
own instruction: fix the questions, not the threshold.

## Minor findings

### m1 · `docs/CONTINUE-HERE.md` carries stale Part-1 claims — RESOLVED 2026-09-13
The file was retired; its durable half (verified sources, failed sources, decisions, authoring
contract, verification checklist) became `docs/AUTHORING.md`, and the spent handoff sections

  modules:" — self-contradictory, and the list that followed is gone
- line 26: "The loop that produced modules 1–3" — now the loop that produced all 14

### m2 · The lab build is not reproducible
`npm run labs:build` rewrites all 20 archives and the manifest with different hashes **and
different sizes** (e.g. `m02-elf-firstlook` 3265 → 3267 bytes), leaving a 21-file diff. The
compiler flags chosen for reproducibility (`-ffile-prefix-map`, `-fno-ident`, per
`ORIGINAL-PLAN.md` §5) are defeated at the zip layer by embedded timestamps. Consequence: any
contributor who runs the build dirties the tree, and the SHA-256 shown to learners changes for
reasons unrelated to content. Fix would be a fixed zip timestamp (`7z -mtm=off` or equivalent).

### m3 · Single 612 KB JS chunk
The bundle grew 349 KB → **612 KB** (Vite warns past 500 KB). Every module's prose, all 125
questions, all 83 lab answers and all 20 walkthroughs load on first paint. Route-level code
splitting per module would cut first load substantially. Not urgent for a static site.

### m4 · `src/services/progress.ts` cannot be imported by bare Node
It imports `../content` as a directory, which Node rejects (`ERR_UNSUPPORTED_DIR_IMPORT`); Vite
resolves it. So `parseProgressJson` — the single validation gate on both load and import — has
no direct test path outside a browser. It was verified through the running app instead and
behaves correctly. Adding the explicit `/index.ts` would make the gate unit-testable.

### m5 · Module 14 breaks the documented lesson convention
Its last lesson is `capstone`, not `practice-lab`. Every other module conforms. This looks
deliberate and reads well — but `CLAUDE.md` states the convention without the exception, so
either the doc or the module should change.

### m6 · Open items from the previous handoff are still open
- **`1995630.png` remains in history at `179fbed`** — third-party artwork of unknown licence, in
  a now-public repo under MIT + CC BY-NC. Removing it now needs a force-push.
- **No README screenshot** — still the biggest presentation gap.
- **CSP is still report-only.** Flipping it needs the `blob:` export check noted in
  `public/_headers`.
- `package.json` `homepage` was fixed to the real repository URL. Resolved.

## Method notes

Three times a first result looked like a defect and was not. Recorded because the distinction
matters:

1. **m06's key appeared rejected.** `unlock.exe 0x24633f10` exits 2. The program formats with
   `%08X` and `strcmp`s, so it accepts `24633F10`; the site's `hex` normaliser lowercases, so a
   learner typing what the tool prints is graded correct. Verified by calling the real
   `isAccepted` from `src/lib/labAnswer.ts`.
2. **Managed artifacts appeared to exit 0 for wrong keys.** A shell-quoting mistake in my loop.
   Direct runs give `invalid`/exit 2 and `serial bad`/exit 2.
3. **Injected junk ids appeared to survive.** That is the documented skip-persist-on-mount
   guard; once any real state change occurs the filtered state is written and all four junk ids
   are gone.

Also corrected mid-audit: my first two attempts to measure `SOURCES` quality used regexes that
undercounted (`https?://` misses domains written bare), producing a false "0 sources" signal for
modules 6, 10–14. Their headers are in fact among the most thorough in the project.

No repository files were changed by this audit. The working tree was restored after the
reproducibility test (`git checkout -- public/labs src/content/lab-manifest.ts`).
